# 独立运动小程序

当前阶段两个小程序并行使用。原小程序全部功能保留；此目录只承载步数、激励广告和卡密延期，账号创建及微信扫码绑定继续在原小程序完成。

## 配置与启动

1. 微信开发者工具导入本目录。第二个小程序的 AppID 已配置为 `wxd3930ae211ea7b0c`，原小程序仍为 `wx6d7e2eacac4b36ff`。真实微信登录、跨小程序跳转和广告需要完成以下服务端及微信后台配置。
2. 服务端私有环境文件配置 `SPORTS_APP_ID`、`SPORTS_APP_SECRET` 和第二个小程序自己申请的 `SPORTS_APP_REWARDED_VIDEO_AD_UNIT_ID`。AppSecret 不放进客户端、Git 或聊天。
3. 第二个小程序后台配置 request 合法域名 `https://dabai.discordbot.cn`，核对隐私声明、服务类目和流量主广告位。
4. 服务端执行 `npx prisma migrate deploy --schema server/prisma/schema.prisma`，生成 Prisma Client，构建并发布 API。新增的两张表不会覆盖现有用户、会员或运动账号。
5. 发布带跳转入口的原小程序体验版，以及第二个小程序体验版；生产代码的跳转目标是 `release`，体验联调时两个入口应使用目标项目对应的 `trial` 版本。测试结束恢复 `release`。

未配置第二个 AppID 和 Secret 时，后端不展示迁移入口，原功能照常工作。`config.js` 配置 API 域名和原小程序 AppID；第二个 AppID 必须与原小程序不同。

## 账号关联

原小程序已绑定用户点击“准备关联账号”，服务端创建有效期两分钟的一次性随机凭证，只在数据库保存 SHA-256 摘要。用户再次点击确认后，通过跳转的 `extraData` 传递凭证，不在 URL 中传登录令牌、密码或用户 ID。

第二个小程序用自己的 `wx.login` 凭证换取微信身份，并在事务中兑换关联凭证。凭证不可重复使用，不允许覆盖已有账号关联；双方均有 UnionID 时必须一致。没有 UnionID 时，一次性凭证本身是用户确认关联的授权，应由用户保管，不应分享给其他人。

也可手动关联：原小程序运动页点击“显示绑定码”，复制 12 位绑定码，在第二个小程序首次进入的关联页面输入并确认。绑定码有效期 5 分钟，只能使用一次；支持大小写、空格和分组横线。重新生成会撤销该用户尚存的旧关联凭证（包括未兑换的跳转凭证），不影响已经完成的账号关联。绑定码使用 60 位随机性，数据库仅保存带独立命名空间的 SHA-256 摘要，接口限制生成及兑换频率；无需新增数据库迁移。手动关联使用同一微信身份校验、关联冲突和受限令牌规则。

关联完成后再次直接打开第二个小程序也能登录。新令牌仅允许访问账号视图、步数操作、广告授权和卡密兑换，不能访问订单、提现、原账号绑定或虚拟支付。现有会员和每日步数数据按原用户 ID 共用。广告完整观看由客户端 `onClose.isEnded` 判断，延续现有后端授权机制；这不是广告平台服务端回调验真。

## 验收与后续切换

管理后台“运营配置”提供“第二个小程序公开体验”开关，默认关闭。开启后所有未关联用户都可直接输入并提交演示目标，表单仅显示“目标 / 输入目标 / 提交”，不展示独立的模式提示卡；提交结果明确注明演示及不修改真实账号数据。演示数据只保留在当前页面，不调用改步、广告授权、卡密或账号接口。用户仍可通过页底“账号关联”入口使用真实服务，已有登录或跳转凭证按正常关联流程处理。此开关不识别审核人员或区分审核/正式环境，不隐藏真实服务；提审说明应同时说明公开演示和真实服务的用途及关联步骤。配置由现有 Setting 表持久保存，无需新增数据库迁移。

公开体验仍需从 `https://dabai.discordbot.cn/api/sports-app/config` 拉取开关，因此第二个小程序必须配置 request 合法域名。业务域名校验不能替代 request 域名配置。

- 已绑定老用户从原小程序进入，账号、会员和今日步数一致；第二个小程序单独重开后仍可登录。
- 未绑定用户、不同微信账号、过期凭证和重复凭证都有明确提示。
- 真实设备完成步数操作，并核对微信运动实际结果。
- 完整观看第二个小程序的真实广告位才能解锁；中途关闭不发授权；一次授权仅消费一次，失败可重试。
- 第二个小程序的令牌无法访问订单、提现或绑定接口。

以上全部通过后，才将 `SPORTS_LEGACY_ACTIONS_ENABLED=false` 并更新原小程序。该开关隐藏原运动操作面板并拒绝原登录态的步数/广告接口，保留登录、账号绑定及其他原功能；改回 `true` 即可恢复。若第二个 AppID/Secret 缺失，开关自动回落为保留原功能。

本阶段不执行下架、不关闭原小程序、不切换该开关。若以后要停用整个原小程序，需要先将账号绑定、新用户入口和客服一起迁移，不能直接停掉。

原小程序运动页提供自助解绑入口，每位用户累计最多 3 次，超过后通过页面客服联系管理员解绑。次数存储在 `User.sportsSelfUnbindCount`，重新注册运动账号和管理员解绑都不会重置额度。解绑删除本系统旧 Zepp 身份与凭据，保留会员权益，下一次绑定注册全新账号；第二个小程序仍通过“返回原小程序管理账号”进行解绑。发布此功能前须应用 `20261005100000_sports_self_unbind_limit` 数据库迁移。

原小程序也支持在对话里输入“解绑账号”“帮我解绑运动账号”“解除 Zepp Life 绑定”。对话先检查账号及额度并弹出确认框，确认后调用同一自助解绑接口；取消确认不会消耗次数。“不要解绑”“怎么解绑”等否定或询问只返回说明，超过 3 次会在对话中提供联系客服入口。

验证命令：`npm run check:sports-miniprogram`、`npm run check:miniprogram`、`npm run typecheck --workspace=server`、`npm test --workspace=server -- --run tests/sports-app.test.ts tests/sports-binding.test.ts tests/api.test.ts`。
